# Security Policy

## Сообщение об уязвимости

Не публикуйте security issue, если оно содержит или может раскрыть пароли, OAuth-токены, authorization codes, Client Secrets, содержимое реальной почты либо другие чувствительные данные.

Используйте private vulnerability report через вкладку **Security** репозитория: [Report a vulnerability](https://github.com/Morfiuskz/Pochta/security/advisories/new). Если private reporting недоступен, создайте обычный issue только с просьбой предоставить приватный канал связи — без технических деталей уязвимости и без секретов.

В сообщении укажите:

- затронутую версию и платформу;
- краткое описание влияния;
- воспроизводимые шаги на тестовых данных;
- ожидаемое и фактическое поведение;
- при необходимости безопасный proof of concept без реальных credentials.

Никогда не прикладывайте реальные пароли, токены, OAuth-коды, Client Secrets, почтовые базы или личные письма. Срок исправления заранее не гарантируется, но сообщения будут рассмотрены по мере возможности.
